Orientation

Overview & principles

The platform is a thin set of new subsystems bolted onto Context Graph's existing governance primitives. It has three runtime subsystems — integration, flow runtime, graph/audit — and one authoring subsystem — the Studio — plus the packaging layer that ties a domain's artifacts into Apps.

Five principles carry over from the resolved decisions and constrain every component:

  1. Ports & adapters. Every new subsystem is defined by an interface (a Protocol) with a lean default adapter; the demo uses in-process adapters, production can swap them (bus → broker, run-store → durable engine) without touching callers.
  2. No unbounded LLM at runtime. The model appears only as a declared agent Action with a typed contract; everything else is deterministic. decision 0/3
  3. One diff gesture. Authoring, migration, and re-approval are the same operation — review a diff to a typed, versioned artifact — served by one engine. decision 4/5/7
  4. Everything is recorded. Every ingress mapping, gateway evaluation, task, state transition, agent call, and approval writes a quad (h,r,t,rc) — the run and the authoring history are both replayable.
  5. Pin the version above. Runs pin flow/block versions; Apps pin the meta-DSL; nothing auto-changes under a running instance. decision 4/6

Data model

Core schemas

Dataclasses, following the schema.py convention. Times are passed in (pure functions take no server clock), IDs are caller-supplied or content-hashed.

Event & ingress events/

@dataclass
class Event:
    type: str              # "request.submitted" — matches a flow's on_event
    payload: dict          # raw (pre-map) or ontology-typed (post-map)
    source: str            # connector id
    ts: str                # ISO-8601, supplied by the connector
    idempotency_key: str   # dedupe key (connectors re-deliver)
    workspace: str         # domain
    app_id: str | None = None   # routing target (else fan-out by type)
    mapped: bool = False       # has the mapping layer run?
    mapping_meta: dict | None = None  # {method, confidence, block_version}

Flow definition flows/

@dataclass
class FlowNode:
    id: str
    kind: str               # event | task | gateway | timer | state
    ref: str | None = None   # action_id | rule_id | state_name | duration
    config: dict = field(default_factory=dict)   # assignee, timeout, ...

@dataclass
class FlowEdge:
    src: str; dst: str
    when: str | None = None   # gateway branch label ("exceeds" / "else")

@dataclass
class FlowDefinition:
    id: str; version: int
    on_event: str
    nodes: list[FlowNode]
    edges: list[FlowEdge]
    test_cases: list[dict] = field(default_factory=list)  # behaviour gate for re-approval

Run (a live flow instance) flows/

@dataclass
class Run:
    run_id: str
    app_id: str; flow_id: str

Artifact diff (the one gesture) studio/

@dataclass
class ArtifactDiff:
    kind: str              # ontology | rule | flow | action | app
    artifact_id: str

Ports & adapters

Interfaces (ports)

Each subsystem is a Protocol with a lean default adapter. This is the seam every "swap later" decision hangs on.

class EventBus(Protocol):
    async def publish(self, e: Event) -> None: ...
    def subscribe(self, event_type: str, h: Handler) -> None: ...
    # default: InProcessBus ; later: RedisStreamsBus / NatsBus

class IngressLog(Protocol):          # durable, at-least-once — decision 2
    async def append(self, e: Event) -> bool: ...   # False = idempotency_key seen
    async def replay(self, since: str) -> AsyncIterator[Event]: ...

class Connector(Protocol):           # extends webingest connector base
    async def poll(self) -> list[RawRecord]: ...      # or push via webhook route

class Mapper(Protocol):              # raw record → ontology-typed — decision 3
    async def map(self, rec: RawRecord, onto: Ontology) -> Mapped: ...
    # DeterministicMapper (field map + coerce) | AgentMapper (reuses AgentSpec)

class FlowExecutor(Protocol):
    async def start(self, flow: FlowDefinition, e: Event) -> Run: ...
    async def advance(self, run: Run) -> Run: ...   # walk to next wait/terminal

class RunStore(Protocol):            # durability seam — decision 1
    async def save(self, run: Run) -> None: ...
    async def get(self, run_id: str) -> Run: ...
    async def due_timers(self, now: str) -> list[Run]: ...

class DiffEngine(Protocol):          # authoring = migration = reapproval — decision 4/5/7
    async def propose(self, kind, intent, current) -> ArtifactDiff: ...
    async def assess(self, d: ArtifactDiff) -> ArtifactDiff: ...   # sets behaviour_changed
    async def apply(self, d: ArtifactDiff, signer: str) -> int: ...  # → new version
◆ The two adapters that matter for "later"
EventBus (in-process → broker) and RunStore (in-memory/JSON → durable engine). Because both are ports, the durability decisions (#1, #2) become one-file swaps, not rewrites — exactly what the "revisit trigger" language in those decisions promised.

Authoring time

Authoring & the diff-and-approve engine

Authoring (Stage 1), migration (a platform upgrade), and re-approval (a changed block) are the same three calls on DiffEngine — only ArtifactDiff.origin differs. That is why one engine serves all three, and why the Studio, the migration tool, and the re-approval prompt are one UI.

Isolation

Namespaces & tenancy

Three-tier addressing over the existing per-workspace isolation — no change to the isolation mechanism, only a naming convention above it.

Domain   = workspace          # CG + ontology + block catalog (L1)   → LIGHTRAG-WORKSPACE
 └ Project = grouping           # all apps in the domain (the solution)
    └ App   = app-id            # an L2 composition (bundle)
       └ Run = run_id           # a live flow instance

Shared blocks are free within a domain (same workspace). Cross-domain sharing (a marketplace ontology) rides on the App-bundle export format and is deferred. The demo is one Domain / one Project / one App.

The trust surface

Determinism & audit

Deterministic by construction
  • rule evaluation, gateways, state transitions
  • the executor's walk (given the same run + inputs)
  • deterministic ingress maps
  • replay: re-walk history → identical result
Non-deterministic but contained
  • agent Actions (typed I/O, confidence, fallback)
  • agent ingress mapping (same contract)
  • trust = containment + validation + audit, not replay
  • low confidence → human task, never silent

Every hop — map, gateway, task, transition, agent call, approval — writes a quad (h,r,t,rc) with supporting_sentences/provenance. The audit trail is not a bolt-on; it is the same graph the platform reasons over.
